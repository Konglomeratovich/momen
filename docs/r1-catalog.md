# Каталог `r1`

`assets/r1.gz` остаётся исходным совместимым каталогом Podkop, а
`assets/r1.lst` — его точным распакованным представлением для Tachyon rule-set
и других клиентов. Оба файла содержат один и тот же упорядоченный набор.

## Зафиксированные свойства

- строк: 724;
- уникальных строк: 724;
- порядок: лексикографический;
- пустых и синтаксически некорректных строк: 0;
- SHA-256 `assets/r1.gz`:
  `026e1b9f7bcdfb2f86ff6b1e61df360a19fa63f079c544d38ee7c55f8091b27c`;
- SHA-256 `assets/r1.lst`:
  `aaa17d6a89fdd62211b10e7b7fd9cefe62e9169c6cf550a92983560bf89bf2ee`;
- `assets/r1.lst` побайтно равен `gzip -dc assets/r1.gz`;
- `happ/data/momen-direct` содержит те же 724 домена с префиксом `domain:`.

Эти свойства проверяет GitHub Actions. Локально их проверяют команды:

```sh
python tools/audit-r1.py --no-dns --write-lst assets/r1.lst
python -m unittest tests.test-audit-r1 -v
```

## Проверка актуальности 3 ноября 2026 года

Проверка выполнена без автоматического изменения каталога:

1. Google DoH и Cloudflare DoH независимо запрашивали A, AAAA, MX и NS;
2. каталог сопоставлен с текущими исходниками
   [`v2fly/domain-list-community`](https://github.com/v2fly/domain-list-community/commit/f9486122931b6fc7d8733731ea58caef4ad33936)
   на commit `f9486122931b6fc7d8733731ea58caef4ad33936` и
   [`itdoginfo/allow-domains`](https://github.com/itdoginfo/allow-domains/commit/eb64def4353f8e1b9cc483858021979a3481c76e)
   на commit `eb64def4353f8e1b9cc483858021979a3481c76e`;
3. результаты DNS использовались только как сигнал для ручной проверки.

Итог:

- 706 записей имеют DNS-ответ;
- 706 записей найдены хотя бы в одном из двух свежих upstream-источников;
- 16 записей без DNS-ответа всё ещё присутствуют в актуальном upstream;
- 16 записей вне этих upstream имеют DNS-ответ;
- две записи требуют отдельного решения владельца каталога.

Совпавшие у обоих DNS-провайдеров 18 записей без обычного положительного
ответа не удалены автоматически. Шестнадцать из них остаются в свежих
профильных списках и могут быть суффиксами, защитными или служебными доменами:

Исторические исключения:

- `alfabank.oavdo.amc` — идентификатор Android-приложения из
  [старого отчёта о банковском трояне](https://www.quickheal.com/blogs/android-banking-trojan-targets-232-apps-including-indian-banks/),
  ошибочно имеющий синтаксис доменного имени; DNS возвращает NXDOMAIN;
- `sberpay.ru` — исторический платёжный домен, отсутствующий в двух проверенных
  upstream и возвращающий NXDOMAIN у обоих DNS-провайдеров.

Они сохранены только потому, что текущая публикация должна быть точным
распакованным представлением существующего `r1.gz`. Их удаление является
отдельным изменением состава каталога: оно должно одновременно обновить
`r1.gz`, `r1.lst`, HAPP-источник, закреплённые хеши, счётчики и миграционные
проверки.

## Почему NXDOMAIN недостаточно

Rule-set применяет правило к домену и его поддоменам. Apex может не иметь
адреса, в то время как рабочие поддомены существуют; защитный или CDN-домен
может активироваться только по событию. Поэтому автоматическая очистка по
одному DNS-прогону способна сломать маршрутизацию.

`tools/audit-r1.py` намеренно завершает structural/source-проверку независимо
от DNS-статуса и помещает сомнительные результаты в секцию `dns.review`.
Временные JSON-отчёты игнорируются Git и не публикуются.
